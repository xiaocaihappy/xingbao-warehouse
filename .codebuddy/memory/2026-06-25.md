### 断网环境关闭按钮无响应修复
**根因**：`main.js` close 事件处理器中 `event.preventDefault()` 拦截关闭后发送 `window:close-request` 给渲染进程，等待 `window:confirm-close` 回执。断网时 Supabase WebSocket 重连或网络请求可能阻塞渲染进程事件循环，导致 IPC 消息无法处理，关闭永久卡住。

**修复**：
1. **main.js**：关闭确认超时 5 秒强制退出；检查 webContents 是否已销毁/崩溃
2. **updater.js**：`checkForUpdates` 使用 `Promise.race` + 15 秒超时，断网不挂起
3. **supabase.js**：realtime 重连策略限制（5次后改30s间隔），防 WebSocket 无限重连
4. **App.jsx**：`checkSession()` 添加 8 秒超时，确保断网时 loading 能结束
5. **Dashboard.jsx**：关闭监听器注册顺序前置，不依赖 Supabase 初始化结果

### v1.1.8 在线更新 latest.yml 超时修复 — 重试 + 手动兜底 + 安全回滚

**诊断发现**：latest.yml 获取超时 (10s) 是核心问题，GitHub CDN 在部分网络环境下下载缓慢。

**修复方案（5 文件修改）**：

1. **updater.js 重写**（核心，~380 行）：
   - `checkForUpdates()` 增加 3 次指数退避重试（2s/4s/6s）
   - `fetchLatestYmlManually()` 手动下载 latest.yml 作为兜底（绕过 electron-updater 内置逻辑）
   - `fetchLatestReleaseTag()` 获取最新 Release 标签用于构建版本直链 URL
   - `parseLatestYml()` 手动解析 YAML 获取版本号/SHA512
   - `isNewerVersion()` 简易 semver 比较
   - `cleanupDownloadCache()` 安全回滚：SHA512 失败时清理 `userData/pending/` 缓存
   - 修复诊断中 latest.yml URL（支持重定向跟进 + 多 URL 尝试）
   - 防并发：`_checkInProgress` 锁防止重复检查
   - 超时从 15s 升到 18s，手动兜底超时 20s

2. **main.js**：新增 `update:cleanup-cache` IPC handler

3. **preload.js**：暴露 `cleanupUpdateCache()` API

4. **UpdateNotifier.jsx**：
   - 新增重试中状态提示（第 N/3 次）
   - 新增 `🗑 回滚` 按钮（手动清理下载缓存）
   - 错误消息追加重试次数

5. **package.json**：版本 → 1.1.8

**更新流程（修复后）**：
```
用户触发检查 → autoUpdater.checkForUpdates()
  ├─ 成功 → 正常流程
  └─ 超时 → 第2次重试 (2s后)
       ├─ 成功 → 正常流程
       └─ 超时 → 第3次重试 (4s后)
            ├─ 成功 → 正常流程
            ├─ 超时 → 手动兜底
            │    ├─ 获取 Release 标签
            │    ├─ 直链下载 latest.yml
            │    ├─ 解析版本/SHA512
            │    ├─ 版本比对 → 有新版本 → emit available
            │    └─ 版本相同 → emit no-update
            └─ 手动兜底也失败 → emit error
```

**安全回滚链路**：
- SHA512 校验失败 → `cleanupDownloadCache()` 自动清理 `pending/`
- 手动回滚按钮 → `update:cleanup-cache` IPC → 删除全部缓存文件
- `downloadUpdate()` 异常捕获 → 调用 `cleanupDownloadCache()`

### v1.1.8 自定义主题背景色无效修复

**根因**：`body` 和 `.login-container` 元素的 `background` 在 CSS 中是硬编码的渐变色（`#0f131a`/`#eaf2f8`），没有引用 `--background` CSS 变量。`Settings.jsx` 的 `applyThemeVarsCore` 确实正确设置了 `--background` 变量（line 87），但没有任何 DOM 元素使用 `var(--background)`，导致调整滑块后背景色不变。

**数据流断裂点**：
```
滑块 onChange → updateCustomField() → applyCustom() → applyThemeVarsCore()
  → root.style.setProperty('--background', bgHsl)  ✅ 变量已更新
  → body { background: linear-gradient(#0f131a, ...) }  ❌ 硬编码，不读变量
```

**修复（2 文件）**：

1. **`index.css`**（3 处）：
   - `body` background → `linear-gradient(135deg, hsl(var(--background) / 0.95), hsl(var(--background)), hsl(var(--background) / 0.95))` + `transition: background 0.4s ease`
   - `.login-container` background → 同上（登录页背景也跟随主题）
   - `body.theme-light` / `.theme-light body` background → 同上（亮色主题不再硬编码 `#eaf2f8`）

2. **`Settings.jsx`**（2 处，`applyThemeVarsCore` 内）：
   - 亮色分支 `--bg: '#eef4f8'` → `--bg: \`hsl(${bgHsl})\`` （同步背景 HSL）
   - 深色分支 `--bg: 'hsl(220, 25%, 8%)'` → `--bg: \`hsl(${bgHsl})\`` （同步背景 HSL）

**修复后数据流**：
```
滑块 onChange → updateCustomField() → applyCustom() → applyThemeVarsCore()
  → root.style.setProperty('--background', '220 25% 8%')
  → body { background: linear-gradient(hsl(220 25% 8% / 0.95), hsl(220 25% 8%), ...) }
  → ✅ 背景色实时跟随滑块变化，0.4s 平滑过渡
```

**构建**: ✅ 通过，零 lint 错误

### v1.1.8 断网状态下关闭按钮无效修复（根本原因修正）

**上一版诊断错误**：v1.1.6 的修复只加了主进程 5 秒超时兜底，但这只是"兜底"，用户体验极差（点击 X 后 5 秒无任何反应）。真正的根因是关闭监听器作用域问题。

**真正根因**：关闭请求监听 (`onCloseRequest`) 仅注册在 `Dashboard.jsx` 组件内。当用户处于以下状态时，渲染进程没有监听器：
- Login 页面（未登录）
- AppLoader loading 态（session 检查的 8 秒内）
- 任何 Dashboard 未挂载的场景

此时 `mainWindow.on('close')` → `send('window:close-request')` → **无人响应** → 唯一的退出路径是主进程 5 秒超时。

**修复数据流变化**：
```
修复前:
  main.js → send('window:close-request') → Dashboard.jsx (仅登录后)
                                           → Login.jsx     ❌ 无监听
                                           → AppLoader     ❌ 无监听
  → 5s 超时强制退出（用户体验：点击X后5秒无响应）

修复后:
  main.js → send('window:close-request') → App.jsx (顶层，时刻监听)
  → 弹窗立即出现 → 用户点击退出/最小化 → confirmClose IPC → 立即执行
  → 3s 超时仅作为极端场景最后兜底
```

**修改（3 文件）**：

1. **`App.jsx`**：
   - 新增 `showCloseDialog` 状态
   - 新增顶层 `useEffect` 注册 `onCloseRequest` 监听（独立于 session 检查，不依赖登录态）
   - 新增全局关闭弹窗 JSX（minimize / quit / cancel 三按钮，与 Dashboard 原有逻辑一致）
   
2. **`Dashboard.jsx`**（减负）：
   - 移除 `showCloseDialog` 状态
   - 移除 `onCloseRequest` 监听注册（注释说明已提升至 App 层）
   - 移除关闭弹窗 JSX 整段（59 行）
   
3. **`main.js`**：
   - 超时从 5s 缩短至 3s（关闭监听已全局注册，通常情况下即时响应）

**构建**: ✅ 通过 (68 modules)，零 lint 错误
