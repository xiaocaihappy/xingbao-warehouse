## 修复 发布.bat 闪退问题
- **根本原因**：
  1. 双反斜杠路径问题：`cd /d "%~dp0app"` 在 BAT 双击运行时，`%~dp0` 末尾有反斜杠，拼接成 `\\app` 导致部分 Windows CMD 解析失败
  2. 错误输出被吞：`>nul 2>&1` 让失败信息不可见
  3. 缺少全程 pause 兜底，失败时窗口一闪而过
  4. 版本号解析脆弱：`findstr "version"` 匹配到 `version:patch` 脚本行
  5. 缺少 git user.name/email 预检
  6. npx electron-builder 在 Windows 中文路径下偶发闪退无日志
- **修复方案**（步骤从5步改为6步，每步加 errorlevel + 日志 + pause 兜底）：
  1. 路径规范化：`cd /d "%~dp0."` + `cd app`（消除双反斜杠）
  2. 预检：token.txt + git user.name/email（缺失则 pause 退出）
  3. 精确版本号匹配：`findstr /R /C:"\"version\":"`（Node 测试已验证能避开 version:patch 行，正确解析出 1.1.13）
  4. 每个 git/npm/vite/electron-builder 命令都有 errorlevel 检查
  5. 失败时 `type` 推送日志文件 + pause 保持窗口
  6. npx electron-builder 用 `cmd /c` 包裹，输出到 `%TEMP%\xingbao_build.log`，失败时 PowerShell 读取最后50行显示
  7. file 等待从 2 秒增加到 5 秒（避免 app.asar 占用）
  8. 全程 12 个 pause 兜底，绝不闪退
- 已用 Node.js 模拟 findstr 验证：精确匹配到 `  "version": "1.1.13",`，成功避开 version:patch 脚本行

## 修复 发布.bat 因 token 占位符导致的推送失败
- **用户反馈**：运行 发布.bat 时窗口报错后停留，截图显示 main 分支推送失败
- **根本原因**：
  1. `token.txt` 内容还是 `# placeholder`（UTF-8 with BOM），没有替换为真实 GitHub Token
  2. 原脚本用 `findstr /V /B /C:"#"` 过滤注释行，但 BOM 导致 `#` 不在真实行首，过滤失败
  3. git push URL 变成 `https://# placeholder@github.com/...`，`#` 被当作 URL fragment，`placeholder@github.com/...` 被 git 解析为 refspec
  4. `echo --- 推送日志 ---` 中的前导 `---` 在某些 CMD 环境下可能被解析，截图出现 `'---' is not recognized as an internal or external command`
- **修复方案**：
  1. 新增 `scripts/read-token.js`：用 Node.js 读取 token.txt，自动去掉 BOM、跳过空行和 `#` 注释行
  2. 发布.bat 改用 `node "..\scripts\read-token.js"` 读取 GH_TOKEN
  3. 检测到 `placeholder` 占位符时立即 pause 退出，并提示用户到 https://github.com/settings/tokens 生成 Token
  4. 把所有 `echo --- ... ---` 分隔符改成 `echo [推送日志]`、`echo [推送日志结束]`、`echo [打包日志 最后 50 行]`、`echo [日志结束]`，避免 CMD 解析问题
  5. 撤销由失败运行产生的 v1.1.14 commit，版本号回退到 1.1.13
- **测试验证**：
  - Node.js 读取脚本正确过滤 `# placeholder`，GH_TOKEN 为空，触发占位符检测
  - 十六进制确认 token.txt 含 UTF-8 BOM（`EF BB BF`）
- **提交记录**：`598acb1` fix: 修复发布.bat token读取 - 过滤BOM和注释行，检测placeholder占位符，去掉echo ---分隔符
- **用户下一步操作**：把 `d:\Desktop\AIBC\星堡移印仓储系统\token.txt` 里的 `# placeholder` 替换为真实 GitHub Personal Access Token（需要 `repo` 权限），然后再运行 `发布.bat`
